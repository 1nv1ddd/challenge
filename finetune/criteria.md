# Критерии оценки: «стало ли лучше» после файнтюна

Задача файнтюна — заставить `gpt-4o-mini` генерировать код **в стиле проекта
challenge** (конвенции из `CLAUDE.md`), а не абстрактный «правильный» Python.
Сравниваем ответы модели ДО (baseline, `baseline_outputs.md`) и ПОСЛЕ дообучения
на одних и тех же 10 примерах eval.

## По чему меряем

### 1. Формат вывода (бинарно, must-have)
- [ ] Ответ — **чистый код без обёртки** ` ```python … ``` ` и без пояснений вокруг.
- [ ] Модуль начинается с русского docstring + `from __future__ import annotations`
      (там, где это модуль целиком, а не отдельная функция/роут).
- [ ] Код **парсится** (`ast.parse` без ошибок).

### 2. Конвенции проекта (чек-лист, чем больше — тем лучше)
- [ ] `snake_case` для функций/переменных, `PascalCase` для классов, приватные — с `_`.
- [ ] DTO — через `@dataclass`; интерфейсы — `ABC` + `@abstractmethod`.
- [ ] FastAPI-роуты — `APIRouter`, ошибки — `HTTPException(status_code=…, detail="русский текст")`.
- [ ] Доступ к SQLite — через хелперы `scheduler_store` (`_connect`, `init_schema`),
      SQL **параметризованный** (`?`), без f-string в запросах.
- [ ] Современные type hints: `str | None`, `list[dict]`, `AsyncIterator[...]`.
- [ ] Исключения ловятся точечно и пробрасываются через `from exc`.

### 3. Антипаттерны (штраф, must-not)
- [ ] Нет `except:` / `except Exception` без нужды.
- [ ] Нет `print()` в коде приложения.
- [ ] Нет `Any` в аннотациях.
- [ ] Нет выдуманных несуществующих хелперов вместо реальных (`fetch_all_tasks` и т.п.).
- [ ] Нет невалидных импортов (`from typing import list`).

### 4. Стиль/близость к эталону (мягкая метрика)
- Визуальное совпадение структуры с reference-ответом (та же идиома, те же имена функций).
- Опционально: эмбеддинг-близость `answer` ↔ `reference` (косинус), как численный прокси.

## Как считаем итог
- **Формат (раздел 1)** — проходной барьер: если ответ обёрнут в ```-фенсы или не
  парсится, пример засчитывается как fail независимо от остального.
- **Конвенции/антипаттерны** — доля выполненных пунктов чек-листа усредняется по 10 примерам.
- «Стало лучше» = средняя доля выполненных пунктов после > baseline **и** формат-барьер
  проходят ≥ 8 из 10 примеров (у baseline, судя по `baseline_outputs.md`, барьер формата
  проваливается почти везде — есть куда расти).

## Что видно в baseline уже сейчас (эталонные провалы для сравнения)
- Ответы завёрнуты в ` ```python … ``` ` — провал раздела 1.
- Изобретаются несуществующие функции/импорты — провал раздела 3.
- `except Exception` и `raise HTTPException(...)` без `from exc` — провал раздела 3.
- Пропущены `from __future__ import annotations` и русский docstring — провал раздела 2.

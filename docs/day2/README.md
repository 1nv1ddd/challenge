# Day 2 — Profiles (субагенты)

**Дата:** 2026-07-21. Челлендж advance, неделя 8.

Профиль в Claude Code = субагент, файл в `.claude/agents/*.md`: YAML-заголовок
(`name`, `description`, `tools`) + системный промпт. Ключевое: **`tools` — это не подсказка,
а физическое ограничение**. Профилю `research` не дали Edit/Write, и он, найдя по пути реальный
баг, не смог его починить, даже если бы захотел. Инструкция «не правь код» так не работает.

## Результат прогонов

**`bugfix`** получил только симптом («во фронте ветка создаётся успешно, но её нет; когда не передан
идентификатор чекпоинта») — без указания файла. Сам дошёл до `app/routers/hub.py:142`, где ошибка
валидации возвращалась как `return {"error": ...}` с HTTP 200, починил в 1 строку по образцу
соседнего `rag_compare` (`hub.py:66-70`), добавил регрессионный тест, прогнал весь сьют.
Перепроверено main-агентом независимо: **50 тестов OK**, эндпоинт отдаёт **HTTP 400**.

**`research`** ответил: покрыто **3 эндпоинта из 21**, единственный `TestClient` во всём наборе —
в `tests/test_mcp_orchestration.py`. Главное в ответе — не число, а различение:
логика за роутами покрыта юнит-тестами, а сам HTTP-слой не покрыт вообще; тесты входят в цепочку
**в обход** роутов.

Побочный эффект: оба профиля независимо сошлись на одном и том же дефекте `POST /api/branches` —
`bugfix` как на причине симптома, `research` как на аномалии стиля.

## Главный вывод дня

Профили сработали с первого раза, но разбор показал, что **часть результата держалась не на
инструкции, а на здравом смысле модели**: агент сам догадался откатить правку и показать красный
тест, сам прибрал тестовые данные из `data/`, сам пометил догадку как догадку. Всё это — лотерея,
которая в следующий раз может не выпасть. Поэтому правки после успешного прогона (см.
[profile-changes.md](profile-changes.md)) — не косметика, а перевод «повезло» в «гарантировано».

Второй вывод, из Day 1 он же: сильнее всего в профиле работает пункт
**«найди в проекте эталон правильного поведения и чини по его образцу»**. Он превращает задачу
«почини» в «почини так, как принято в этом репозитории» — и снимает главный риск субагента,
который пишет корректный, но чужой для проекта код.

## Открытые хвосты

1. **`review` не проверен прогоном.** Новые субагенты подхватываются только при старте сессии
   Claude Code — горячей перезагрузки нет (проверено фактом: `Agent type 'review' not found`,
   в списке доступных только `bugfix` и `research`). Прогнать первым делом после рестарта,
   на диффе этого же дня.
2. **`.claude/` в `.gitignore`** (строка 12) — то есть сами профили в репозиторий не попадают,
   а они и есть артефакт задания. Решить, снимать ли игнор.

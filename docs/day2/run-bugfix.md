## Что агент сделал (28 tool-вызовов, ~3.5 мин)

1. Воспроизвёл до правки: `curl -X POST /api/branches` без `checkpoint_id` → `HTTP 200` + тело `{"error": ...}`.
2. Проверил фронт: `static/index.html:1947-1968` — `fetch` без проверки статуса внутри `try/catch {}`,
   поэтому 200 не бросает исключение и UI рисует успех. Это объяснило слово «выглядит успешно» из симптома.
3. Нашёл корневую причину: `app/routers/hub.py:142`.
4. Доказал, что это выпадение из стиля, а не решение: `grep -rn 'return {"error"' app/` → ровно одно совпадение.
5. Нашёл эталон рядом: `app/routers/hub.py:66-70` (`rag_compare` → `HTTPException(400, detail="русский текст")`).
6. Починил диффом в 1 строку по образцу эталона.
7. Написал регрессионный тест `tests/test_branch_api.py`, проверил его красным на `git stash`-версии.
8. Прогнал весь сьют. Прибрал за собой тестовый разговор `diag-repro` из `data/agent_memory.json`.

## Оценка прогона

**Сработало (заслуга профиля, а не удачи):**

- «Сначала воспроизвести» → агент не начал чинить с догадки.
- «Искать причину, а не место симптома» + «найти эталон правильного поведения рядом» →
  фикс сделан по образцу `rag_compare`, а не изобретён. Это самый ценный пункт профиля:
  он превращает «почини» в «почини так, как принято в этом репозитории».
- «Минимальный дифф» + «не рефакторить попутно» → рядом лежали три соблазна
  (`except Exception` в `mcp_panel.py`, ручной разбор body, `resp.ok` во фронте) — все ушли
  в раздел «Риски», ни один не был исправлен «заодно».
- Жёсткий формат отчёта → раздел «Риски и что НЕ трогал» сам вытащил соседний дефект
  того же эндпоинта (неизвестный `checkpoint_id` → HTTP 500) — то, о чём не спрашивали.

## Вопрос

> какие эндпоинты не покрыты тестами

## Ответ агента (18 tool-вызовов, ~1.5 мин) — выжимка

**21 HTTP-эндпоинт всего**, покрыты тестами через HTTP только **3**:
`POST /api/mcp/connect`, `GET /api/mcp/status`, `POST /api/mcp/disconnect` —
все в `tests/test_mcp_orchestration.py:60-110`, единственном месте, где вообще поднимается `TestClient(app)`.

**Не покрыты 18:** все 16 из `app/routers/hub.py` (включая `POST /api/chat`, `GET /api/models`,
`POST /api/rag/compare`, весь блок веток/чекпойнтов/памяти/профилей/инвариантов/task-state)
и оба из `app/scheduler_routes.py` (`/ping`, `/stream`).

Ключевое разделение, которое агент сделал сам: **логика за роутами частично покрыта юнит-тестами
(агент, RAG, `scheduler_store`), а HTTP-слой — нет.** Тесты входят в цепочку в обход роутов:
`tests/test_rag_compare.py:38` бьёт прямо в `agent.compare_rag_answers`, минуя `POST /api/rag/compare`.

Следствия, которые агент вытащил без наводки:
- `app/payloads.py` не импортируется ни одним тестом → вся валидация 400/503 в `hub.py:62-70` и `:91-99` не проверена;
- MCP-роутер покрыт только по happy-path: ветки ошибок (`app/mcp_panel.py:146-158`, `_resolve_script` :40/:50/:55/:57) — нет;
- оба SSE-эндпоинта без тестов вовсе, включая обработку исключений в стриме (`app/routers/hub.py:53-54`).

Честность: агент явно пометил `conftest.py`-вывод как «это вывод, не факт из кода» и написал,
что покрытие инструментально не измерял — вывод статический, из сопоставления списка роутов
и вызовов `client.(get|post)` в `tests/`.

## Побочная валидация

В разделе «Пробелы и наблюдения» агент независимо заметил тот самый баг, на котором параллельно
работал профиль `bugfix`:

> `POST /api/branches` при пустом `checkpoint_id` возвращает `{"error": ...}` с HTTP 200
> (`app/routers/hub.py:141-142`) вместо `HTTPException(400)`, как в остальном коде.

Два независимых профиля сошлись на одном дефекте — read-only профиль нашёл его как аномалию стиля,
bugfix — как причину симптома. При этом `research`, увидев баг, **не стал его чинить** (инструментов
правки у него нет намеренно) — контракт «только чтение» отработал.

## Оценка прогона

**Сработало:**

- Инструментальное ограничение (`tools: Read, Grep, Glob`) сильнее любой инструкции «не правь код»:
  агент физически не мог сорваться в починку, увидев баг.
- «Каждое утверждение со ссылкой `файл:строка`» → ответ проверяем, а не пересказ.
- «Разделять факт и вывод» → агент сам пометил догадку про `conftest.py` как догадку.
- «Проверять смежные слои» → нашёл главное: покрытие есть, но в обход HTTP-слоя. Без этого пункта
  ответ был бы «покрыто 3 из 21» без объяснения, почему это не так страшно, как звучит.

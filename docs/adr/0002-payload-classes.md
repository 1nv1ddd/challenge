# 0002 Payload-классы для разбора тел запросов

## Status
Принято и внедрено (Day 5). Все POST-обработчики в `app/routers/hub.py` переведены на payload-классы.

## Контекст
Обработчики FastAPI разбирали тело запроса вручную: `body = await request.json()` и затем
цепочки `body.get(...)` прямо в функции роутера. Это порождало три проблемы:
- дублирование логики защиты от не-объектного тела (`body if isinstance(body, dict) else {}`)
  повторялось в восьми местах;
- разбор и валидация полей размазывались по обработчикам, роут переставал быть «тонким»;
- на не-объектном JSON (`[]`, строка) обработчик падал в `AttributeError` → HTTP 500
  (баги, закрытые в Day 5: `/api/checkpoints`, `/api/profiles`).

Эталон уже существовал в проекте — `ChatRequestPayload`/`RagComparePayload` в
[`app/payloads.py`](../../app/payloads.py) с классметодом `.from_body(body)`.

## Решение
Разбор JSON-тела HTTP-запроса выполняется **только** через `@dataclass(frozen=True)`-payload
с классметодом `from_body(body: dict) -> Payload` в [`app/payloads.py`](../../app/payloads.py).
Ручной `body.get(...)` в роутерах запрещён. Нормализация не-объектного тела вынесена в общий
хелпер `as_dict(body)` там же и переиспользуется во всех обработчиках (reuse-first, Инвариант №1).

Обработчик роутера остаётся тонким:
```python
body = await request.json()
p = SomePayload.from_body(as_dict(body))
return agent.do_something(p.field, ...)
```

## Последствия
- Единая точка разбора и дефолтов каждого запроса; роуты читаются как декларации.
- Устойчивость к некорректному телу «бесплатно» (нет 500 на `[]`/строке).
- Payload-классы тривиально тестируются в отрыве от FastAPI (см. `tests/`).
- Новый POST-эндпоинт обязан завести свой payload-класс, а не разбирать dict по месту.

## Альтернативы
- Pydantic-модели в сигнатуре обработчика: мощнее, но проект намеренно держит разбор тела
  тонким слоем без завязки на FastAPI-валидацию (см. докстринг `app/payloads.py`), поэтому
  оставлены лёгкие dataclass-payload'ы.
- Оставить ручной `body.get`: отвергнуто — дублирование и регрессии с HTTP 500.

# Day 5 — Execution loop: автономный прогон пула задач

**Дата:** 2026-07-24. Челлендж advance, неделя 8.

День про то, что собранного за Days 1–4 ассистента (правила `CLAUDE.md`, 5 профилей-субагентов,
`/verify`, локальная модель) пора **измерить в работе**, а не описывать. Заводим пул реальных
задач против этого же репо и гоняем ассистента в execution-loop: взял задачу → выбрал профиль →
выполнил → verify → закоммитил → закрыл Issue → взял следующую. Автономно, без вмешательства и
без правки промптов между задачами. Проект **с нуля не делали** — измеряем именно накопленную
инфраструктуру.

## Пул (микс, 18 задач)

6× тесты (`testgen`), 2× баги (`bugfix`), 4× рефактор, 2× фичи, 3× доки, 1× research.
Все выведены из **реальных пробелов** репо: непокрытый HTTP-слой (Day 2: 3/21 эндпоинта),
антипаттерн ручного разбора `body.get` в 5 обработчиках, 12 модулей без русского докстринга,
рассинхрон `docs/api.md`, отсутствующий `GET /api/scheduler/jobs` при готовом `list_jobs()`.
У каждой задачи — исполнимый критерий «сделано».

## Как выбирался профиль

Детерминированно по типу задачи (без «магии»): `bug→bugfix`, `test→testgen`,
`research→research`, `refactor/feature/docs→оркестратор inline по CLAUDE.md`. Профили —
физически ограниченные субагенты Days 1–2, их промпты между задачами не менялись.

## Главный вывод дня

На **этом** пуле и **этой** базе тюнингованный ассистент прошёл 18/18 автономно. Но чистая
цифра «streak 18» держится в том числе на харнессе: честный лог показывает, что слом едва не
случился на T02 не из-за ассистента, а из-за устаревшей базы, и что часть «зелёного» — заслуга
профилей, которые **отказывались** делать неправильное (testgen не стал закреплять баг тестом).
Побочно прогон вскрыл два реальных дефекта репо (незакоммиченный фикс Day 2; testability-пробел
`MEMORY_PATH` в `bootstrap.py`).

# Правила код-ассистента (локальная модель) — проект AI Chat Hub

> Это системный промпт для локальной модели в IDE (Continue → Ollama → Vikhr-Nemo-12B).
> Он **намеренно короче** проектного `CLAUDE.md`: 12B-модель с Q4-квантованием
> хуже держит длинный контекст и теряет пункты в конце. Здесь — только то, что
> реально ловится на прогонах: инвариант reuse-first, обязательные паттерны, топ-запретов.

Ты дописываешь код в существующий проект: **Python 3.12 + FastAPI + Uvicorn**.
Пиши так, будто продолжаешь соседний файл, а не создаёшь проект с нуля.

## Делай всегда

1. **Сначала ищи готовое.** Перед новой функцией проверь, нет ли похожей в модуле —
   переиспользуй её, не дублируй. Нужно подмножество полей — вызови существующую
   функцию и спроецируй результат в обработчике.
2. Первая строка модуля после докстринга — `from __future__ import annotations`.
3. Однострочный **docstring на русском** в начале модуля: что он делает.
4. Современные type-hints: `str | None`, `list[dict]`. Аннотируй тип возврата.
5. FastAPI-роут: `async def`; ошибки — `raise HTTPException(status_code=..., detail="русский текст")`.
6. Доступ к БД планировщика — **только** через функции `app/scheduler_store.py`.
   Никакого `sqlite3.connect(...)` прямо в роутере.
7. SQL — только параметризованный (`?`). Никаких f-string / конкатенации в запросах.

## Не делай

- Не дублируй уже существующую функцию (нарушение п.1).
- Не пиши голый `except:` или `except Exception` без нужды — лови конкретный тип
  (`ValueError`, `json.JSONDecodeError`, `httpx.HTTPError`).
- Не ставь `print()` в коде приложения.
- Не пиши `Any` в аннотациях, если тип можно уточнить.

## Формат ответа

Верни **один код-блок** с готовым файлом или патчем. Без рассуждений до и после блока.
Если для реюза не хватает функции в сторе — добавь тонкую функцию в `scheduler_store.py`
(через `_connect()`, параметризованный SQL), а не пиши SQL в роутере.

# Day 8 — Routing между моделями

**Дата:** 2026-07-29. Челлендж advance, неделя 8.

Запрос не обязан идти в самую сильную модель. Большая часть вопросов закрывается моделью, которая
дешевле в десятки раз, и задача маршрутизатора — понять, где это так, а где нет. Здесь собран
каскад: сначала отвечает дешёвая модель, и только если уверенности в её ответе не хватает, запрос
уходит на сильную.

Тиры (прайс RouterAI, ₽ за миллион токенов):

| Тир | Модель | Вход | Выход |
|---|---|---|---|
| Дешёвый | `google/gemma-3n-e4b-it` | 6.1 | 12.2 |
| Сильный | `openai/gpt-4.1` | 202.8 | 811.4 |

Разрыв по выходным токенам — **×66**. Именно он делает осмысленной трату лишнего дешёвого вызова
ради того, чтобы не звать дорогую модель.

## Как устроен маршрут

```
запрос
  │
  ├─ pre-routing по тексту (регекспы, 0 вызовов LLM)
  │     маркеров сложности ≥ 2 → сразу сильная модель
  │
  └─ иначе: дешёвая модель, 2 выборки параллельно (основная t=0.2, дубль t=0.8)
        │
        ├─ оценка уверенности по ответу
        │     confidence ≥ 0.7 → отдаём ответ дешёвой модели
        │     confidence < 0.7 → эскалация на сильную
        │
        └─ сильная недоступна → отдаём ответ дешёвой, помечая неудавшуюся эскалацию
```

### Эвристика 1 — pre-routing по тексту запроса

Классификатор без обращения к модели: считает маркеры сложности в самом вопросе — требование кода,
пошаговости, доказательства, проектирования, сравнения, развёрнутого ответа, несколько ограничений,
расчёт в несколько действий, длина > 400 символов, два и более вопросительных знака. Одного маркера
мало — порог равен двум, чтобы «сравни X и Y» не улетало на дорогую модель.

Смысл: на заведомо сложном запросе вызов дешёвой модели — почти гарантированно выброшенные деньги
и лишняя секунда задержки.

### Эвристика 2 — уверенность в ответе дешёвой модели

Системный промпт обязывает модель закончить ответ строкой `CONFIDENCE: 0.NN`. Эта самооценка —
основа, из которой вычитаются штрафы за подозрительные признаки:

| Сигнал | Штраф | Зачем |
|---|---|---|
| Нет строки `CONFIDENCE` | база 0.5 вместо самооценки | контракт нарушен — доверия меньше |
| Ответ оборван (нет терминального знака и нет строки контракта) | −0.4 | упёрлись в лимит генерации |
| Пустой ответ | −0.6 | отвечать нечем |
| «не знаю», «недостаточно данных» | −0.6 | модель сама признаёт незнание |
| Формулировки неуверенности («не уверен», «скорее всего») | −0.25 | hedging |
| Короткий ответ (< 40 символов) на **непростой** вопрос | −0.2 | на «символ золота?» ответ «Au» — норма, на «спроектируй схему» — нет |

Итог ниже **0.7** → эскалация. Правило «если не уверен — эскалируй» реализовано буквально, и причина
эскалации всегда пишется в ответ.

### Эвристика 3 — самосогласованность дешёвой модели

Появилась не из плана, а из замеров: **самооценка мелких моделей насыщена**. В пробе на шести
вопросах `gemma-3n`, `gpt-oss-20b`, `mistral-small`, `llama-4-scout` ошибались в 1–2 ответах из
шести и при этом ставили себе `CONFIDENCE` 0.90–1.0 — то есть на ошибках самооценка не падала.
Эвристика 2 в одиночку такие случаи не ловит.

Поэтому дешёвую модель спрашивают дважды параллельно, и ответы сравниваются: для числовых ответов —
по итоговому числу (последнее число в тексте, чтобы промежуточные шаги расчёта не считались
расхождением), для текстовых — по совпадению состава (Жаккар ≥ 0.5). Расхождение — штраф −0.4,
которого хватает, чтобы даже `CONFIDENCE: 1.0` ушла в эскалацию.

Второй вызов берётся при **повышенной температуре** (0.8 против 0.2 у основного) — из соображения,
что на одной температуре выборки будут слишком похожи и сигнала не дадут. Замеры это соображение
не подтвердили: расхождение прекрасно ловится и при одинаковой температуре, а горячий дубль
добавляет в основном ложные срабатывания. Сравнение обеих конфигураций — ниже.

## Замеры

Датасет — 30 запросов четырёх групп: 8 простых (факты), 8 средних (арифметика, счёт букв, ловушка
9.11 vs 9.9), 8 сложных (многошаговые расчёты, упорядочивание дробей, простые числа), 6 ловушек
(слово задом наперёд, кошки в углах, улитка на столбе, 5 машин за 5 минут). У каждого запроса —
regex-проверка ответа, поэтому точность считается автоматически, а не размечается постфактум.

Сравниваются три стратегии на одних и тех же запросах: **только дешёвая**, **только сильная**,
**роутер**.

Прогонов два, различаются только температурой дубля для проверки согласованности:
**run1** — дубль на той же температуре, что и основной ответ (0.2), **run2** — горячий дубль (0.8).

| Метрика | run1 (дубль t=0.2) | run2 (дубль t=0.8) |
|---|---|---|
| Только дешёвая — верных / цена | 24/30 (80.0%) / **0.081 ₽** | 25/30 (83.3%) / **0.079 ₽** |
| Только сильная — верных / цена | 28/30 (93.3%) / **3.008 ₽** | 27/30 (90.0%) / **2.972 ₽** |
| **Роутер** — верных / цена | **25/30 (83.3%) / 0.603 ₽** | **25/30 (83.3%) / 0.686 ₽** |
| Цена роутера от «всегда сильная» | **20.0%** | **23.1%** |
| Вызовов LLM (дешёвая / сильная / роутер) | 30 / 30 / 61 | 30 / 30 / 63 |
| Latency роутера медиана / макс | 2636 / 10192 мс | 2255 / 11614 мс |
| Потрачено на неиспользованные черновики | 0.012 ₽ | 0.021 ₽ |

Главный размен виден в первых трёх строках: **роутер отдаёт 6.7–10 п.п. точности и забирает
77–80% стоимости.** При этом он не хуже дешёвой модели в одиночку: 25/30 против 24/30 и 25/30.

Latency честнее смотреть по медиане: среднее портит один-два вызова, где RouterAI отвечал 10+ секунд.

| run2 | 25 (83%) | 4 — S06, T01, T03, T06 | 1 — H01 |

Причины каждой эскалации:

|---|---|---|---|

| S06 | Сколько дней в високосном году? (run2) | **365 против 366** — горячий дубль сорвался на вопросе-константе | лишняя |

### Что реально сработало, а что нет

**Самооценка модели не сработала ни разу.** За два прогона дешёвая модель выдала 58 оценок
`CONFIDENCE`, все в диапазоне **0.95–1.0**; ниже порога 0.7 не опустилась ни одна — включая ответы,
которые были неверны. Ни одна эскалация в обоих прогонах не вызвана самооценкой.

**Все эскалации по уверенности вызваны расхождением выборок.** Эвристика, которой не было в
изначальном плане и которая появилась после замера саморепорта, оказалась единственным работающим
сигналом на этом наборе. Из 6 её срабатываний за два прогона полезным оказалось **одно** (T05).

**Горячий дубль даёт больше срабатываний, но в основном ложных.** run1 → run2: эскалаций 2 → 4,
спасённых ответов 1 → 0, лишних 1 → 3, цена 20.0% → 23.1% от «всегда сильная», точность одинаковая
(25/30). На этом датасете горячий дубль купил не точность, а расходы.

**Pre-routing сработал один раз из 30 — и промахнулся.** Запрос H01 («3 коробки по 12 яблок,
17 продали, добавили 2 по 8») ушёл на сильную модель по маркерам «пошагово» + расчёт в несколько
действий, но дешёвая модель в обоих прогонах отвечала на него верно. То есть единственное
срабатывание этой эвристики оказалось лишней тратой: ~0.14 ₽ вместо ~0.005 ₽.

## Честные ограничения

1. **На этом наборе «всегда дешёвая» — лучший вариант по деньгам, и роутер её почти не обыгрывает.**
   25/30 против 24/30 в run1 и 25/30 против 25/30 в run2 — при цене в **7.5–8.7 раза выше**.
   Роутинг окупается там, где дешёвая модель регулярно проваливается, а здесь она проваливается
   редко. Честный вывод дня: ценность каскада определяется не эвристикой, а разрывом качества между
   тирами — и его надо мерить до того, как строить маршрутизацию.
2. **Согласованная ошибка не ловится ничем.** Пропущенных эскалаций 5 в run1 и 4 в run2
   (M03, M05, H06, T02 в обоих): обе выборки дешёвой модели дали один и тот же неверный ответ с
   самооценкой 1.0. Это ровно тот режим, против которого бессильны и саморепорт, и согласованность.
   Пример из веб-чата: `/route Сколько букв «с» в слове «ассоциация»?` → «3 буквы» (верно 2), обе
   выборки согласны, confidence 1.0, эскалации нет.
3. **Из пропусков сильная модель исправила бы только часть**: 3 из 5 в run1, 2 из 4 в run2. Остальные
   (M05 «сколько сестёр у брата Марии», T01 «конституция задом наперёд») `gpt-4.1` проваливает тоже,
   так что потолок роутера здесь — 27–28 из 30, а не 30/30.
4. **Ложные эскалации на пустом месте.** S06 «сколько дней в високосном году» ушёл на сильную модель
   из-за того, что горячий дубль выдал «365» вместо «366». Платим цену сильной модели за вопрос,
   который дешёвая знает наизусть. Из 6 эскалаций по уверенности за два прогона полезной была одна.
5. **Pre-routing — это регекспы, а не понимание, и на этом наборе он ушёл в минус.** Он смотрит на
   форму запроса («пошагово», «спроектируй», длина, число вопросов), а не на суть. Единственное
   срабатывание (H01) оказалось лишней тратой, а сложные вопросы, сформулированные просто (H02–H08),
   он спокойно пропустил на дешёвую модель. Эвристика по форме запроса не заменяет проверку ответа.
6. **Ground truth — мои regex-проверки на 30 запросах.** Две из них пришлось чинить уже после первого
   прогона: `«двадцать раз»` (T04) и `«кошек — 4»` (T03) — верные ответы, которые шаблон не засчитывал.
   Цифры до этой правки занижали точность сильной модели, и это ровно та ошибка, которую даёт
   автоматическая проверка без ручной вычитки.
7. **Разброс между прогонами сопоставим с измеряемым эффектом.** На одном и том же датасете точность
   «только дешёвой» — 24 и 25 из 30, «только сильной» — 28 и 27 из 30. Разницу в 1–2 ответа между
   конфигурациями читать как значимую нельзя; уверенно различаются только цены, там разрыв
   в разы.
8. **Проверялись только короткие вопросы с проверяемым ответом.** На генеративных задачах (написать
   текст, код, длинный разбор) ни «итоговое число», ни Жаккар как мера согласия не применимы —
   эвристику пришлось бы строить иначе.

## Как проверить руками

Веб-чат `http://localhost:8000/`, команда `/route`:

```
/route Столица Австралии?
/route Сколько раз цифра 7 встречается в числах от 1 до 100?
/route Спроектируй схему кеширования для 10k RPS и подробно обоснуй выбор
/route
```

В ответ приходит сам ответ и под ним разбор маршрута: кто отвечал, самооценка и итоговая уверенность,
сработавшие сигналы, причина решения и цена (вызовы / время / токены / рубли).

Через API:

```bash
curl -s -X POST http://localhost:8000/api/route -H 'Content-Type: application/json' \
  -d '{"question":"Сколько букв «о» в слове «молокоотсос»?"}'
```

Прогон датасета (обе конфигурации):

```bash
python docs/day8/run_eval.py --consistency-temperature 0.2 --out run1.json && python docs/day8/report.py run1
```

```bash
python docs/day8/run_eval.py --out run2.json && python docs/day8/report.py run2
```

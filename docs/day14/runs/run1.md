# Прогон 1 — первый запуск, до правок

Генератор `openai/gpt-4o-mini`, ревьюер `openai/gpt-4.1`, до 3 попыток на задачу.
Данные: [`run1.json`](run1.json).

| Задача | Итог | Попыток | Что поймал security review |
|---|---|---|---|
| `save-token` | ❌ не принято за 3 попытки | 3 | `plaintext_secret_storage` — трижды подряд |
| `log-requests` | ✅ закоммичено | 2 | `secret_in_log`, `pii_in_log` |
| `call-partner-api` | ✅ закоммичено | 2 | `tls_verification_off` |

14 вызовов модели, 3.64 ₽. Все — через шлюз, ни одной блокировки на входе.

## Что сломалось

Принятый артефакт задачи `call-partner-api` оказался **нерабочим**:

```python
def fetch_partner_data(client_id: str, api_key: str) -> dict | None:
    url = f'[REDACTED_URL]'          # ← сюда шлюз подставил плейсхолдер
    headers = {'Authorization': f'Bearer {api_key}'}
```

Output guard шлюза увидел в ответе модели ссылку `https://api.partner.example/v1/clients/…`,
не нашёл её хост в allowlist и **замаскировал прямо в коде**. Тесты этого не заметили: они
подменяют httpx мока́ми, и URL им безразличен. Security review тоже не возразил — он получил уже
замаскированный код, а `[REDACTED_URL]` выглядит как осознанная заглушка.

Три слоя проверок пропустили сломанный модуль, потому что **сломал его сам защитный слой**.

## Вывод, который поменял архитектуру

Guard, написанный для человека в чате, нельзя без изменений ставить на машинный поток. Для чата
маскирование — правильное поведение: пользователь всё поймёт по плейсхолдеру. Для кода
маскирование — порча артефакта.

Правка: у `guard_output()` появился режим `enforce=False` («только отчёт») — находки считаются,
пишутся в аудит и в отчёт цикла, но текст не правится. Критичные находки (`prompt_leak`,
`dangerous_command`) блокируют ответ в обоих режимах: из них вырезать нечего.

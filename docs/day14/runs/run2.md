## Все три ветки цикла отработали

- **Critical/High → возврат на генерацию.** `tls_verification_off` в строке 8: «Отключена проверка
  TLS-сертификата (verify=False) при обращении к внешнему API» → вторая попытка вернула `verify=True`.
- **Medium/Low → пропускаем с warning.** `missing_timeout` попал в шапку артефакта:
  `# Warning (не блокирует): [medium] В httpx.get не указан таймаут.`
- **Чисто → коммитим.** `log-requests` со второй попытки.

## Проблема прогона: ревьюер сдался

`save-token` принят на третьей попытке. Что именно приняли:

```python
DB_FILE = 'tokens.db'

def save_token(user_id: str, token: str) -> None:
    init_db()
    with sqlite3.connect(DB_FILE) as conn:
        conn.execute('REPLACE INTO tokens (user_id, token) VALUES (?, ?)', (user_id, token))

def create_secret_file(filename: str, content: str) -> None:   # ← никем не вызывается
    fd = os.open(filename, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
```

Токен по-прежнему лежит **в открытом виде**, просто теперь в SQLite вместо json. Плюс мёртвая
функция с правами `0600`, которая к токену не применяется. Две предыдущие попытки ревьюер
блокировал по `plaintext_secret_storage`, а на третьей поставил «чисто».

Это ложноотрицательное срабатывание — и не случайное. Ревьюер видит в контексте, что код уже
дважды правили по одному замечанию, и начинает засчитывать движение в сторону исправления за
исправление. Ровно та же уступчивость, из-за которой в чатах «уговаривают» модель.

## Вывод, который поменял цикл

Повторный проход по одному и тому же правилу — не повод дать ещё один шанс, а сигнал, что задача
не решается генерацией. Добавлено правило: **одно правило блокирует `LOOP_REPEAT_ESCALATION` = 2
попытки подряд → статус `escalated`, задача уходит человеку.** Цикл не даёт ревьюеру дойти до
третьего круга, где тот начинает соглашаться.

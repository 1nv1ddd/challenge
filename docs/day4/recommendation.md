# Рекомендация: для чего хватает локальной модели

Вывод из прогона — **не «локальная плохая»**, а «локальная хороша на другом классе задач».
Vikhr-Nemo-12B (Q4) на M-серии даёт бесплатный, приватный, офлайновый ассистент со скоростью
~15 ток/с. Ошибка — сажать её на ту же работу, что и облако. Ниже — где она окупается, а где нет.

## ✅ Локальной хватает

- **Черновики и бойлерплейт под присмотром.** Набросать каркас функции/теста/эндпоинта,
  который ты всё равно вычитываешь и правишь. Форму она берёт (в прогоне — 404, `HTTPException`,
  параметризованный `?`), детали чинишь сам.
- **Точечные вопросы «что делает этот кусок».** Объяснить сниппет, накидать regex, вспомнить
  синтаксис — без ухода кода в сеть.
- **Приватный / офлайновый режим.** Код, который нельзя отправлять наружу (NDA, секреты, работа
  в самолёте). Здесь локальная — не «хуже облака», а единственный допустимый вариант.
- **Массовые дешёвые прогоны.** Прогнать сотню файлов через один и тот же промпт, где стоимость
  облачного API кусается, а качество каждого ответа некритично.
- **Обучение и эксперименты с промптами.** Крутить системный промпт и правила без счётчика денег.

## ❌ Локальной НЕ хватает (бери облако)

- **Многофайловые задачи с архитектурным выбором.** В прогоне модель ушла в ловушку — сырой SQL
  в роутере вместо слоя стора. Reuse-first и «положи доступ к БД в правильный слой» она не держит.
- **Строгое следование длинным конвенциям.** Полный CLAUDE.md 12B не тянет — теряет пункты
  (отвалились `from __future__`, docstring, русский detail). Даже на ужатых правилах — 2 из 8.
- **Ответ, который сразу компилируется.** Плейсхолдеры `# ... остальной код` и незакрытые импорты
  (`NameError`) ⇒ apply-патч в IDE ломается. Нужен ручной догляд каждый раз.
- **Autocomplete (tab-подсказки).** Vikhr — не FIM-модель, для inline-комплита непригодна вообще.
- **Финальный код в PR без вычитки.** Как автономный агент, пишущий в main, — нет.

## Практический сетап (что реально включить)

1. **Локальная (Vikhr-12B) = chat/edit в Continue** для приватных черновиков и вопросов — уже
   настроено ([continue-config.yaml](continue-config.yaml)), правила в системном промпте.
2. **Autocomplete — отдельная FIM-модель**, если нужен tab-комплит:
   `ollama pull qwen2.5-coder:7b-base` и добавить с `role: autocomplete`. Vikhr для этого не годится.
3. **Облако — для «серьёзного»:** многофайловые правки, строгий стиль, код в PR, автономные агенты
   (профили Day 2–3). Разделение по задаче, а не «или-или».
4. **Правила под локальную держать короткими** и императивными ([rules-local.md](rules-local.md)) —
   на слабой модели длина правил бьёт по качеству, а не помогает.

## Одной строкой

> Локальная 12B — это **бесплатный приватный джуниор-черновик под обязательную вычитку**.
> Всё, где важны архитектура, строгий стиль проекта или «работает из коробки», — облако.
